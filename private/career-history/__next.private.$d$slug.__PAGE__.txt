<h2>1. 공개 API 무중단 전환 : PHP → Kotlin, Spring</h2>
<p><code>〔기간〕</code> · <code>역할 : 〔주도 / 참여, 팀 N명〕</code>
<code>Kotlin</code> <code>Spring Boot</code> <code>〔JPA 등 데이터 접근 기술〕</code> <code>MySQL</code> <code>〔캐시 저장소〕</code> <code>Kotest</code> <code>Testcontainers</code> <code>Spring REST Docs</code> <code>Swagger</code> <code>GSLB</code> <code>OpenSearch</code></p>
<h3>해결한 문제</h3>
<ul>
<li>외부 파트너 앱이 상점의 상품·게시판 데이터를 다루는 <strong>공개 Open-API가 PHP 레거시</strong>였습니다.</li>
<li>운영하는 동안 같은 종류의 결함이 반복됐습니다.
<ul>
<li>주문 조회 API의 스펙 누락, 응답 누락, 오류</li>
<li>상품 등록 시 입력값 검증 누락</li>
</ul>
</li>
<li>연관 데이터를 반복해서 조회하는 <strong>N+1 쿼리 구조</strong> 때문에 응답이 느렸습니다.</li>
<li>코드가 중복되고 계층 간 책임이 모호해서, 기능을 하나 추가해도 고칠 곳이 많았습니다.</li>
</ul>
<h3>중요성과 제약</h3>

<h2>4. 파트너 API 호출량 제한·버저닝·구버전 종료</h2>
<p><code>2025</code> · <code>역할 : 〔주도 / 참여〕</code> · <code>Kotlin</code> <code>Spring Boot</code></p>
<h3>해결한 문제</h3>
<ul>
<li>API <strong>호출량 제한</strong>을 도입해야 했지만, 앱별 호출 현황이 파악되어 있지 않았습니다.</li>
<li>요청·응답 필드명을 정리하기 위해 <strong>API 버전을 새로 만들어야</strong> 했습니다.</li>
</ul>
<h3>중요성과 제약</h3>
<ul>
<li>구버전을 쓰는 앱을 한꺼번에 차단하면 그 앱의 <strong>실제 서비스가 장애</strong>를 겪습니다.</li>
</ul>
<h3>의사결정</h3>
<ul>
<li><strong>계측 먼저, 제한은 그다음</strong> : 앱별 호출량을 파악한 뒤 제한 기준을 정하고 개발자 가이드를 업데이트했습니다.</li>
<li><strong>구버전 종료 순서</strong> : 신·구 버전 함께 운영 → 종료 일자 공지 → 앱별 구버전 호출량 추적 → 종료 일자에 맞춰 차단</li>
</ul>
<h3>결과</h3>
<ul>
<li>대상 앱 〔N〕개, 종료일 기준 구버전 호출 앱 〔N〕개</li>

<h2>5. PHP 7.0 → 8.2 버전업 &#x26; 암호화 데이터 전환</h2>
<p><code>〔기간〕</code> · <code>역할 : 〔주도 / 참여〕</code> · <code>PHP 8.2</code> <code>OpenSSL</code></p>
<h3>해결한 문제</h3>
<ul>
<li>솔루션이 보안 지원이 끝난 <strong>PHP 7.0</strong>에서 운영되고 있었습니다.</li>
<li>기존 암호화에 쓰던 <strong><code>mcrypt</code> 확장은 PHP 7.2부터 제거</strong>되어, 버전을 올리려면 암호화 방식부터 바꿔야 했습니다.</li>
</ul>
<h3>중요성과 제약</h3>
<ul>
<li>이미 암호화되어 저장된 데이터(〔데이터 종류〕)를 <strong>손실 없이</strong> 새 방식으로 옮겨야 했습니다.</li>
<li>대상 규모 : 〔상점 N개 / 데이터 N건〕</li>
</ul>
<h3>의사결정</h3>
<ul>
<li><strong><code>mcrypt</code> → <code>openssl</code>로 교체하고 기존 데이터를 마이그레이션</strong>했습니다.
<ul>
<li>〔호환성 검증 방법 : 알고리즘·모드·패딩 확인 등〕</li>
<li>〔겪은 문제가 있다면 : 예) 패딩 방식 차이로 복호화 결과가 달라진 문제〕</li>
</ul>
</li>
<li><strong>버전업 자동화</strong> : 〔무엇을 자동화했는지 : 상점별 반복 작업 스크립트화 등〕</li>
</ul>
<h3>결과</h3>
<ul>
<li>〔N〕개 상점 전환 완료, 데이터 불일치 〔0건〕</li>
<li>상점당 작업 시간 〔N → M〕</li>
